# 개인용 Android 영어 학습 앱 요구사항과 Phase 1 계획.

작성일은 2026-10-22이며 Phase 1과 Phase 2를 구현하고 실기기 검증을 진행한다. 사용자는 WebView 대신 Android 네이티브 학습 화면을 명시적으로 선택했다. 첨부한 기존 화면의 배치와 기능을 우선한다.

## 확정한 요구사항.

- 개인 갤럭시에 APK로 직접 설치한다.
- 기존 사이트의 두 코스, Day·카드 이동, 정답 보기, 역순·무작위, TTS, 글자 크기, 테마, 복습 통계를 유지한다.
- 저장된 자료로 오프라인 학습한다. 자료 갱신은 사용자가 수동으로 실행한다.
- 영어회화와 기본동사를 모두 각 Notion 원문에서 가져온다.
- 코스·Day별 복습 횟수와 최근 복습 시각, 마지막 완료 챕터를 Notion에 저장한다.
- 삼성 인터넷의 기존 통계·설정·마지막 완료 챕터를 앱으로 이전한다.
- 화면 기본값은 다크 모드·글래스모피즘·Pretendard이며 기존 테마 설정이 있으면 이전한다.
- 스토어 배포, 학습 자료 편집, 공부 중인 카드 위치 저장은 이번 확정 범위에 포함하지 않는다.

## 현재 확인한 근거.

- 기존 앱은 HTML/CSS/Vanilla JS와 localStorage를 사용한다. Notion 자동 동기화 스크립트는 기본동사만 처리하며 GitHub Actions가 6시간마다 실행한다.
- 웹 Refresh는 배포된 data.json을 다시 읽는다. 앱의 Notion 갱신은 별도의 통신 연결이 필요하다.
- 진도는 reviewStats:<courseId>의 Day별 count·lastReviewed와 lastCompletedChapter의 courseId·day다.
- 기준선은 npm test 58/58 및 npm run check 통과다. ADB 실행은 가능하나 연결된 기기는 없었다. 모델·OS·화면·음성은 미검증이다.
- Notion 본문을 읽어 두 교재 모두 Day 토글과 한국어/영어 컬럼을 사용하는 것을 확인했다.
  - 영어회화 원문. https://www.notion.so/2c63d76f887480e9a373d924affa523e
  - 기본동사 원문. https://www.notion.so/32f3d76f88748069b726d6b6d47f5afd
  - 영어 인덱스. https://www.notion.so/989c69acd3cc4d67a0850fa87d330b90

## 최종 인터뷰 결정.

1. Android 네이티브 UI로 새로 구현한다. 기존 웹의 동작을 Kotlin과 Jetpack Compose로 옮기며 WebView는 사용하지 않는다.
2. 영어 인덱스 아래 ‘영어 학습 진도’ 전용 데이터베이스를 새로 만든다. 생성 위치와 목적은 사용자 승인 범위다. Phase 2 진입 시 원문 보존과 생성 후 재조회로 검증한다.

## 제안하는 구조와 동작.

설치형 Android 앱에 네이티브 학습 화면·자료·폰트를 포함한다. 실행 시 Pages에 접속하지 않는다. data.json은 빌드 때 앱 assets에 포함하고 화면은 Compose로 구현한다. 현재 웹 UI는 기록 내보내기에 필요한 부분만 추가한다.

```text
index.html / script.js / backup.js   기존 웹 UI와 기록 내보내기.
android/                            Android 앱 빌드 설정.
  app/src/main/java/.../            Compose 화면, 학습 상태, 데이터·진도, TTS.
  app/src/main/res/font/            오프라인 Pretendard.
  app/build/generated/.../          빌드 시 포함하는 현재 data.json.
  app/src/test/                     학습 동작·기록 유효성 검사.
tests/                              기존 웹 회귀 검사와 내보내기 검사.
```

- Compose의 네이티브 텍스트·버튼·목록·대화상자로 학습 화면을 구성한다. Android 12 이상을 대상으로 배경을 별도 레이어에서 실제로 흐리고 그 위에 선명한 콘텐츠를 배치한다.
- 한국어·영어 음성 목록과 재생은 Android TextToSpeech로 연결한다. 기존 속도·자동 읽기 설정은 유지하되 설치되지 않은 목소리는 다시 선택할 수 있게 알린다. 오프라인 음성 사용 여부는 기기의 음성 데이터 설치 상태로 검증한다.
- Notion 연결은 개인용 integration 키를 앱 설정에서 직접 입력하는 안을 제안한다. 채팅·소스·APK에 키를 넣지 않는다. Android Keystore 키로 암호화해 앱 전용 저장소에 보관하고 웹 화면에는 키를 전달하지 않는다. 필요한 원문과 진도 저장 위치만 연결한다.
- 자료와 진도는 구분한다. 수동 동기화는 자료 가져오기와 진도 보내기를 제안하며, 각 작업의 성공·실패를 별도로 표시한다. 진도 전송 시점은 최종 계획에 명시한다.
- 자료는 조회·변환·검증을 마친 뒤 저장본을 교체한다. 통신 실패·빈 결과·해석 오류가 나면 마지막 정상 자료와 진도를 유지한다.
- 진도는 동일 코스·Day에 다시 전송해도 복습 횟수가 누적 가산되지 않게 현재 값을 저장한다. 학습 중 전송이 겹치면 다음 수동 전송에 최신 상태가 포함되도록 처리한다.
- 기록 이전은 웹의 허용된 통계·설정 키만 JSON 파일로 내보내고 앱의 파일 선택으로 가져온다. 크기·형식·값 검증과 미리보기를 거쳐 반영한다. 삼성 인터넷 원본 기록은 유지한다. 음성 식별자는 기기에서 사용 가능 여부를 검사한다.

## Phase 1 구현 계획.

목표는 현재 자료로 독립 실행하는 APK에서 기존 학습 동작과 기록 이전이 검증되는 것이다.

1. Android 프로젝트와 네이티브 화면을 추가하고 초기 자료·Pretendard를 앱에 포함한다. 검증은 APK 빌드와 인터넷 차단 상태의 첫 실행이다.
2. 기존 학습 UI와 저장 동작을 연결하고 Android TTS를 붙인다. 검증은 두 코스의 카드·챕터 이동, 정답, 순서, 복습 완료, 재실행 복원과 양 언어 재생이다.
3. 웹 내보내기와 앱 가져오기를 구현한다. 검증은 정상 왕복, 손상 파일 거부, 원본 보존, 가져온 통계·설정·완료 챕터의 일치다. 실제 브라우저 기록 이전에는 내보내기 기능이 있는 웹 버전의 배포가 필요하다.
4. 최종 APK를 실기기에 설치한다. 접기·펼치기 중 상태 보존과 화면 캡처를 통해 실제 블러·폰트·대비·잘림·버튼·키보드 포커스를 확인한다. 기기 연결이 안 되면 실기기 검증 완료로 표시하지 않는다.

## Phase 2와 전체 완료 기준.

Phase 1 검증 뒤 두 Notion 원문 조회·변환, 앱 인증정보 저장, 수동 자료 갱신과 진도 전송을 구현한다. 현재 파서에서 재사용 가능한 부분만 공유하고 기존 Actions 동기화는 유지한다.

전체 완료는 두 코스의 실제 Notion 갱신, 테스트용 복습 완료 후 실제 Notion 진도 조회 확인, 중복 전송으로 횟수 증가 없음, 오프라인·권한 오류·통신 중단 시 자료 보존, 기존 기록 이전, 마지막 수정 후 빌드한 APK의 실기기 실행으로 판단한다. 원문 내용은 수정하지 않는다.

## 현재 검증 상태.

- Node 60개, Android 단위 10개, 격리된 에뮬레이터 화면 테스트 4개가 통과했다. 서명 release APK의 인터넷 차단 첫 실행과 실제 파일 선택기를 통한 웹 백업 가져오기·복습 3회 표시를 확인했다.
- 실제 휴대폰에 release APK를 설치했다. 사용자가 앱에 키를 직접 입력한 뒤 두 코스 Notion 자료 가져오기 완료를 확인했다.
- 최신 서명 APK를 실기기에 업데이트 설치했다. 사용자는 기존 기록 이전 후 통계·마지막 완료 챕터 일치와 물리적 접기·펼치기 후 카드·정답 유지, 배치, 한국어·영어 음성 정상을 확인했다. 첨부한 실제 백업에는 글자 크기 설정 2개만 있고 복습·완료 기록은 없다.
- 사용자가 ‘전송할 복습 기록이 없습니다’ 안내를 확인했다. 실제 학습 완료 기록의 Notion 저장과 중복 전송 검증은 아직 남아 있다. 최종 실기기 화면 캡처·키보드 포커스도 별도 미검증이다.
