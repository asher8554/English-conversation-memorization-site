# Notion 타임아웃 단계적 대응 설계

## 목표

같은 Notion API 30초 타임아웃이 세 번 연속 발생할 때만 해당 실행에서 요청 단계 로그와 한 번의 재시도를 사용한다.

## 범위

- GitHub Actions 캐시에 최근 연속 타임아웃 횟수를 저장한다.
- 동기화 성공 또는 타임아웃이 아닌 실패는 횟수를 0으로 초기화한다.
- 직전 두 실행이 Notion 30초 타임아웃이면 세 번째 실행에서만 상세 로그와 한 번의 재시도를 켠다.
- `data.json` 형식과 일반 동기화 경로는 바꾸지 않는다.

## 검증

- 타임아웃 판별과 재시도 모드 결정을 Node 테스트로 고정한다.
- `npm test`와 `npm run check`를 실행한다.
- 수동 GitHub Actions 실행이 정상 동기화 경로를 유지하는지 확인한다.
